## Later

| Idea | Why it isn't in 1.0 |
|---|---|
| Real scan progress (percent, current file) | `MpCmdRun` reports nothing while it scans. Defender's own progress is only available to administrators through other interfaces. 1.0 shows the running time. |
| Restore / remove quarantined items from Hallow Guard | Needs admin (`MpCmdRun -Restore`) - and Windows Security already does it well. 1.0 opens Protection history. |
| Disable machine-wide startup entries, tasks and services | Needs admin and a careful undo for each kind. 1.0 opens Windows' Startup apps page for machine-wide entries. |
| Catalog signatures | Windows files signed through security catalogs (not inside the file) are treated as "part of Windows" by their folder. Checking the catalog itself would make that exact. |
| Browser extension store check online | 1.0 trusts the store update address in the manifest; 1.2 also reads the browser's own `from_webstore` / `location` (done offline). Asking the store would need network calls per extension. |
| Countries for connections | Needs an IP-to-country map: Windows has none offline, and an online lookup would send your connections out. 1.2 shows internet vs local network, and names only when you click Look up names. |
| Turn on Controlled folder access / add folders from Guard | Changing Defender's settings needs admin and isn't Guard's job - 1.2 explains it and opens Windows Security's Ransomware protection page. |
| Hallow Vault's exact save folders | Vault 1.12's status.json lists games and install folders, not save folders. Guard 1.2 already reads `saveFolders` / per-game `saveDirs` when Vault adds them; until then it suggests Saved Games and My Games. |
| Hallow Toolkit in the family score | Toolkit has no status file; what it could add (Windows Update, startup clean-up) is already covered by the Windows checks and the leftover hunt. |
| Shield's own numbers (blocked today, lists up to date) | A browser extension can't be asked from a desktop app without a native messaging host; 1.1 reads only whether it's installed, its version and whether it's switched on. |
| Away scan for game-controller-only play | Windows' idle time ignores game controllers. 1.3 covers it by checking known game processes, the full-screen state and Hub's "playing" list; a game none of these know about, played windowed with only a controller, could look idle. |
| Defender's own CPU limit for the away scan | MpCmdRun runs at Idle priority, but the scan itself runs in Defender's service with its own limit (ScanAvgCPULoadFactor). Changing it is a Defender setting - Guard never changes those. |
| Hub / Remote showing the weekly report | 1.3 exposes `report` on the pipe and `lastReport` in status.json; Hallow Hub and Hallow Remote can show it in a later version of theirs. |
| Change hardening settings from Guard (network protection, ASR rules, Guest, SMBv1) | Each needs admin and is Windows' or Defender's own setting - Guard never changes settings. 1.6 explains each one and opens the right page or shows the steps. |
| Exact "has no password" for accounts | Windows' PasswordRequired flag says whether an account *may* have an empty password, not whether it has one; checking for real would mean trying to sign in. 1.6 words it as "Windows marks ... as not needing a password". |
| Hub menu entry | Hallow Hub 2.12's tray menu has a fixed app list. Hallow Guard follows the family protocol (`menu`, `invoke`, `notify`) and hides its own icon only when Hub's `tray-host` answer lists Guard, so it's never left without an icon. |
